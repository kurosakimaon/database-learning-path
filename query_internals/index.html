结丹期 · 查询内幕

给会 C++ 的你：join 算法就是你写过的哈希表与双指针归并， 代价模型就是成本函数选最短路，EXPLAIN 是编译器的 -S 输出， 火山模型算子就是 next() 迭代器，WAL 就是提交前 journal—— 数据库的"大脑"没有魔法，全是工程。

◆ 本关唯一要刻进脑子的一句话：查询优化器是个会计，不是预言家。 它只认估算行数和代价公式，统计一过期，它就能"正确地"选出慢一千倍的计划。 看懂了账本，你才看得懂 EXPLAIN。

算法的账先算清01 实测：块嵌 NL 177.91ms，Hash Join 0.94ms——同数据同结果（48,987 行），差 189 倍。差距全在页账上。
EXPLAIN 是计划的 X 光SCAN 还是 SEARCH、回不回表、要不要临时 B 树——03 用 15 道题、22 条真实输出练成本能。
断电的账最后算04 手写 WAL：提交 = fsync 返回；有 COMMIT 重放、没 COMMIT 丢弃、烂尾截断。恢复三规，一次崩溃全演完。

STEP 01 · 地基
01_join_algorithms.cpp
四种 join 同场竞技：块嵌 NL / Index NL / Sort-Merge / Hash Join，同一份数据（5000×50000，含 2% 悬空外键），比较与页读分栏记账。实测：约 141~178 / 2.8 / 2.4 / 0.7~0.9 毫秒（耗时随负载浮动）——差近 200 倍的真相是页账不是比较账。
★ C++ 单文件g++ 直接编译
STEP 02 · 心脏
02_cost_model.cpp
手写迷你优化器的"会计部分"：代价 = 页×1.0 + 比较×0.005。三轮剧本：过期统计选 C（估 157，真实慢 973 倍）→ 上帝视角看真实账 → ANALYZE 后会计改选 A。这屏数字治百种"计划怎么这么怪"。
★ 本关心脏g++ 直接编译
STEP 03 · 实练
03_explain_drills.sql
真 SQLite（orders 100 万行）上的 15 道 EXPLAIN 题：先"你猜"，再看写死的真实输出与解读。覆盖索引、最左前缀下半句、filesort、驱动表互拍、IN vs EXISTS、深分页改写（实测快 84 倍）。每行输出都实跑核对过。
★ 实测验证sqlite3 可直接跑
TOOL · 最重要的教具
explain_pipeline.html
一条 SQL 的五道工序动画：字符串 → 语法树 → 约束列表 → 优化器打分（A 1,072.5 vs C 152,710）→ 火山模型 next() 箭头流动（BUILD/PROBE/EOF + 实时计数器）→ 结果。14 步，右侧面板同步显示每道工序的输入输出。
交互动画双击即开
STEP 04 · 收尾
04_wal_and_crash.cpp
手写迷你 WAL 引擎：LSN + 校验和、提交 = fsync 返回、随机崩溃注入。五场景实测：REDO 已提交、丢弃未提交、torn write 截尾、NVMe 随机≈顺序（1.0 倍）+ 每笔 fsync 才是大头的真相。附赠结构体 padding 坑一课。

🪜 建议的学习顺序

  1. 通读 tutorial.md——先接受"会计不是预言家"这句命题，带着"计划到底是怎么被算出来的"往下看。
  2. 跑 01_join_algorithms.cpp——四种算法各跑一遍，盯"比较 / 页读"两栏：Hash 赢在哪、Index NL 什么时候翻身（选择性极高时）。
  3. 打开 explain_pipeline.html 点自动播放——先看一遍全流程混个眼熟，特别是火山模型里"黄色箭头向下=next() 调用、绿色箭头向上=行数据"这对关系。
  4. 跑 02_cost_model.cpp——三轮剧本一跑，"估 157 / 真 15 万 / 差 973 倍"这三个数字就刻脑子里了，动画里的代价表瞬间看懂。
  5. 做 03_explain_drills.sql 15 道题——每条先遮住注释自己猜，再对答案；把"SCAN 还是 SEARCH、回不回表"练成本能。
  6. 跑 04_wal_and_crash.cpp 并故意改坏它——做 tutorial 练习3：把 torn_bytes 改小 1 字节，看恢复三规多严格。
  7. 做 tutorial.md 末尾的三道练习——解选择率临界点、改 IN 为 EXISTS 看计划、玩崩溃截断。做完这关才算通关。
