退出码 0 才算过 · 数字必须真实 · 严禁造假

六阶段依赖图

地基 → 房子 → 书架 → 保险柜 → 门面 → 跑道。每一级都踩实了再上下一级，卡住了就回头，别跳级。

六阶段卡片

阶段 1 · 地基

Pager：按页读写一个文件

数据库的地基：4096 字节定长页是唯一读写单位，页 0 放元数据，LRU 页缓存带真实命中率统计，跨页写 200 条记录关掉重开逐条对 checksum。

  • 定长页 / 元数据页 / LRU = 哈希表 + 双向链表
  • 小端序列化 putU16/32/64 · FNV-1a 校验和
  • 源码：phase1_pager.cpp
阶段 2 · 房子

堆表：一行数据到底长什么样

变长字段、NULL、删除三件事逼出页内槽位目录：页头 + slot 目录从前长、记录从后堆。RID = (page_id, slot)，是住址不是身份。

  • 槽位目录 / 变长行编码（位图 + 偏移表）
  • insert / get / delete / scan · 槽位复用
  • 源码：phase2_heap_table.cpp
阶段 3 · 书架

落盘 B+ 树二级索引

把"按值找行"从全表扫描里捞出来。叶子双向链表让范围扫描不回头碰树；扇出按 4KB 页实算；插入"等于往右"、搜索"等于往左"。

  • 叶子/内部两种页格式 · 兄弟链表 · 分裂
  • 实测加速比、树高、每层读页数真实打印
  • 源码：phase3_btree_index.cpp
阶段 4 · 保险柜

预写日志与崩溃恢复

WAL 纪律三条：改页前日志先行并 fsync；commit 只 fsync WAL；恢复按校验和扫日志、撕裂尾截掉、只 REDO 已提交。子进程 exit(9) 模拟真断电。

  • (LSN, page, 前像/后像) 记录 · checkpoint
  • 三种崩溃场景 A/B/C 全部恢复成功才算过
  • 源码：phase4_wal.cpp
阶段 5 · 门面

迷你 SQL 前端

手写 tokenizer + 递归下降解析器：CREATE / INSERT / SELECT（WHERE、ORDER BY、LIMIT）+ EXPLAIN。谓词能下推 B+ 树就 IndexScan，否则 TableScan。

  • 分词 → AST → 逻辑计划 → 流水线执行
  • 中文表格对齐 · 规模实测索引 vs 全表对账
  • 源码：phase5_sql_frontend.cpp
阶段 6 · 跑道

汇总基准 vs SQLite

写入吞吐、点查、范围查、崩溃恢复四组实测对照 SQLite C API；双方都"真死一次"验证恢复。所有差距如实打印、逐项解释、逐项对账。

  • RNG 同种子同序列 · 每组结果双路对账
  • 口径意识：先问比的是不是同一件事
  • 源码：phase6_bench.cpp（-lsqlite3）

编译命令速查

# 阶段 1~5：单文件自包含，零依赖
g++ -std=c++17 -O2 -Wall -Wextra phase1_pager.cpp        -o phase1_pager.exe
g++ -std=c++17 -O2 -Wall -Wextra phase2_heap_table.cpp    -o phase2_heap_table.exe
g++ -std=c++17 -O2 -Wall -Wextra phase3_btree_index.cpp   -o phase3_btree_index.exe
g++ -std=c++17 -O2 -Wall -Wextra phase4_wal.cpp           -o phase4_wal.exe
g++ -std=c++17 -O2 -Wall -Wextra phase5_sql_frontend.cpp  -o phase5_sql_frontend.exe

# 阶段 6：链接 SQLite（msys64 ucrt64 已装 libsqlite3）
g++ -std=c++17 -O2 -Wall -Wextra phase6_bench.cpp         -o phase6_bench.exe -lsqlite3

# 运行：看退出码，别看心情
.\phase5_sql_frontend.exe
echo $LASTEXITCODE   # 0 = 全部对账通过

零警告是及格线；退出码 0 是验收线。 阶段 4 与阶段 6 会自动拉起子进程模拟崩溃，控制台有"进程死亡"字样属正常剧情，别慌。 PowerShell 里中文乱码就先执行 SetConsoleOutputCP(65001)（源码里已自带）。
