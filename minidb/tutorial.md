# 第 7 关 · 手搓期 · MiniDB —— 用 C++ 手搓一个迷你数据库

**师傅开场白：**
你写了几年 SQL，数据库对你来说一直是个"黑盒"。这个毕业设计就是把黑盒拆了，
从第一个字节开始，一块砖一块砖地把地基、房子、书架、保险柜、门面全砌一遍。
六个阶段，难度是爬楼梯，每一级都得踩实了再上下一级。别赶进度，赶进度等于
白做 —— 每个阶段都配了"验收标准"，跑不过就别往下走，回头把卡住的地方
掰扯明白，那才是真正长本事的地方。

## 一、项目简介

MiniDB 是一个教学用的迷你数据库引擎，全部由单个 .cpp 文件构成，没有第三方
依赖（阶段 6 除外，它要拉 SQLite 当对照组）。六个阶段各管一层：

磁盘上长什么样（Pager）→ 一行数据怎么存（堆表）→ 按值怎么快速找行
（B+ 树索引）→ 断电了怎么不丢数据（WAL）→ 用户说的话怎么变成机器动作
（SQL 前端）→ 我们跟工业界差多远（基准测试）。

每个阶段单文件自包含、单文件可编译可运行，退出码 0 就是"全部校验通过"，
非 0 就是有对账失败。记住师傅这句话：别信"看起来对"，信退出码，信你亲手
打出来的数字。所有数字必须是真跑出来的 —— 本项目严禁造假数字，宁可难看，
不可失真。

环境：只要 **C++17 编译器**（参考机为 g++ 15.2 / MSYS2 UCRT64；
MinGW-w64、Clang 亦可）。编译命令统一是

```powershell
g++ -std=c++17 -O2 -Wall -Wextra phaseN_xxx.cpp -o phaseN_xxx.exe
```

Linux/macOS 把 `.exe` 去掉即可。阶段 6 末尾再加 `-lsqlite3`
（需要 SQLite 开发库）。**要求零警告通过，警告当错误对待。**

> 阶段 1/2/3 的文件存在性探测用 `fopen` 而不是 `fstream`：
> 部分 libstdc++ 实现里，`std::fstream` 以 `std::ios::in` 打开不存在的文件时
> `is_open()` 为假但 `failbit` 未置位，`if (!probe)` 会误判成"文件已存在"。
> 这是真实踩过的移植坑，注释里写着，别改回去。

## 二、六个阶段与验收标准

### 阶段 1：Pager —— phase1_pager.cpp

**做什么：** 把"按页读写一个文件"做成可靠的地基。4KB 定长页是唯一读写单位；
页 0 放元数据（magic/version/page_size/page_count）；实现可配容量的 LRU
页缓存；跨页写 200 条记录，关掉重开逐条对 checksum。

**验收标准：**

- 零警告编译，退出码 0；
- LRU 命中率是真实统计（缓存故意给小，小到能看见淘汰和 miss 才算数）；
- 关闭重开后 200 条记录 checksum 一条条对上。

**师傅点评：** 为什么页是 4096？它对齐 x86 内存页和多数文件系统块，
也是常见 4Kn NVMe 盘的原生扇区。对齐写能减少读-改-写放大，
但**不保证**原子：断电仍可能只落下半页，所以阶段 4 才要用
校验和 + WAL 兜底。这个问题面试问烂了，但你亲手写过才算你的。

### 阶段 2：堆表 —— phase2_heap_table.cpp

**做什么：** 现实咬人了 —— 变长字段、NULL、删除。页内套一层槽位目录：
页头 8B（slot_count/delete_count/dead_bytes）+ slot 目录（u32，bit31 标
删除）+ 记录从页尾向前堆。RID = (page_id, slot)，是"物理住址"不是主键。
实现 insert / get / delete / scan，删掉的槽位要能复用。

**验收标准：**

- 1 万行实测，插入/读取/删除/全表扫四关全对，退出码 0；
- 删除后的空间真的被后续插入复用（dead_bytes 会说话）；
- 能亲口讲清：为什么 RID 会因更新、页整理而搬动，二级索引为什么要跟着改。

### 阶段 3：落盘 B+ 树二级索引 —— phase3_btree_index.cpp

**做什么：** 把"按值找行"从全表扫描里捞出来。两种页格式（叶子 kind=2 带左右
兄弟指针，内部 kind=1 带孩子指针），叶子串双向链表；插入下探 + 分裂，
扇出按 4096 页和条目尺寸实算；范围扫描下探到左端点后沿链表向右走。
非唯一 key 就存多条 (key, RID)，天然形成 RID 列表。

**验收标准：**

- users 表 5 万行建索引，5000 次随机点查 + 200 次范围扫描对全表扫；
- 加速比、树高、每层读页数全部真实打印（本机实测：点查约 770 倍、
  范围约 5200 倍、树高 2；这两个比值是耗时之比，受页缓存状态和机器负载
  影响很大，你跑出来可能是几百到上万，如实记下来，别改分母）；
- 双下降规则能讲清：插入下降"等于往右"，搜索下降"等于往左"再沿链表
  向右收 —— 讲不清就是没懂，回去画图。

### 阶段 4：预写日志与崩溃恢复 —— phase4_wal.cpp

**做什么：** 让数据库断电后还能站起来。WAL 纪律三条：改页前先把
(LSN, page_id, 前像, 后像) 追加进 .wal 并 fsync；commit 只 fsync WAL；
恢复时带校验和扫日志，撕裂尾截掉，只 REDO 已提交事务，未提交丢弃。
checkpoint = 脏页落盘 + 写 checkpoint LSN + 截断日志。

**验收标准：**

- 三种崩溃场景全部恢复成功、退出码 0（程序自己拉子进程 exit(9) 模拟
  断电，不跑析构不 flush，和真断电对进程而言没区别）：
  - A 写页中途崩 —— 撕裂页被校验和识破；
  - B 提交前崩 —— 进了 WAL 没 COMMIT 的改动必须被丢弃；
  - C 提交后崩 —— COMMIT 已 fsync 的改动必须被 REDO 找回；
- 能讲清 no-steal 策略下为什么不需要 UNDO。

### 阶段 5：迷你 SQL 前端 —— phase5_sql_frontend.cpp

**做什么：** 手写 tokenizer + 递归下降解析器，支持 CREATE TABLE / 多行 INSERT /
SELECT（投影、WHERE 等值与比较 + AND、ORDER BY [DESC]、LIMIT），EXPLAIN
前缀打印逻辑计划。执行链路：分词 → AST → 逻辑计划（谓词能下推 B+ 树就
IndexScan，否则 TableScan）→ 扫描 → 过滤 → 排序 → 截断 → 投影，中文
表格化输出。

**验收标准：**

- 六节演示全部 ✓、退出码 0；规模实测：灌 2 万行走完整 SQL 链路，
  索引查 400 行 vs 全表查 1 行，行数和手算对账，倍数真实打印
  （参考机实测 0.2 ms vs 4.6 ms，约 26 倍；绝对值随机器波动，
  关键是读页数 804 vs 40190 这个稳定得多的口径）；
- 错误处理三条全踢回：表不存在、列不存在、INT 列塞字符串；
- 这一阶段踩的坑最多（页内覆盖写 SIGSEGV、内部分裂覆盖丢子树、叶子
  分裂左页不回写丢重各 24 条），全修在注释里，认真读。

### 阶段 6：汇总基准 + SQLite 对照 —— phase6_bench.cpp

**做什么：** 把造好的引擎拉上跑道，跟工业界实打实比四件事：写入吞吐（20 万行
+ 双索引）、点查（2 万次）、范围查（200 次）、崩溃恢复（双方都真死一次：
MiniDB 丢脏页靠 WAL REDO，SQLite 子进程 commit 后 ExitProcess 留 -wal）。

**验收标准：**

- 每一项两边结果对账（行数/命中/页内容/COUNT 全对上）、退出码 0；
- 差距如实打印并逐项解释 —— 内存后端赢了落盘 SQLite 的项，注释里
  必须点破口径差；输了就输，数字造假才是丢人。

## 三、文件列表与学习重点

- **phase1_pager.cpp** 定长页、元数据页、LRU 页缓存、checksum 对账。
  重点：小端序列化 putU16/32/64 一族；LRU = 哈希表 +
  双向链表；"命中率是算出来的不是猜出来的"。
- **phase2_heap_table.cpp** 槽位目录、变长行编码（总长|列数|null 位图|偏移表|
  数据区）、RID 语义、删除与空间复用。
  重点：页头空间账必须两头一起算；RID 是住址不是身份。
- **phase3_btree_index.cpp** 两种页格式、兄弟链表、插入分裂、扇出实算、双下降
  规则、范围扫描。
  重点：扇出 = (页大小 - 页头) / 条目大小，是算出来的；
  链表让范围扫描不回头碰树。
- **phase4_wal.cpp** 日志记录格式（LSN/类型/前像/后像/校验和）、fsync
  时序、checkpoint、REDO 恢复、撕裂尾截断。
  重点：WAL 顺序保证 = 追加写 + fsync；恢复的正确性
  靠校验和与 LSN 边界，不靠运气。
- **phase5_sql_frontend.cpp** 分词、递归下降解析、逻辑计划、流水线执行、EXPLAIN。
  重点：谓词下推（选择律）；执行顺序"扫描→过滤→排序
  →截断→投影"每一步为什么不能省、不能换。
- **phase6_bench.cpp** 四组基准 + SQLite C API 对照 + 子进程真崩溃。
  重点：口径意识（比的是同一件事吗）、对账意识
  （每个数字都要有第二条路验证）、RNG 同种子同序列。
- **tutorial.md** 本文件：项目指南。
- **index.html** 自包含导航页：双击就能看，六阶段依赖图 + 卡片 +
  编译命令速查。零外部资源。

师傅交代过的通用坑，都埋在各文件的注释里，这里再点名一遍：

1. isalpha 之类传负数 char 是 UB，先转 unsigned char；
2. 持有 vector 元素引用时再 push_back 可能悬空，deque 才稳；
3. 整数 + 字符串字面量是指针算术，不是拼接；
4. 页内空间账：目录从上长、数据从下长，两边都要记账；
5. 分裂要"先移位再写入"，覆盖写入 = 丢数据；
6. PowerShell 里先 SetConsoleOutputCP(65001)，不然中文全是乱码。

## 四、动手扩展方向

按"投入一个周末能看见效果"排序，别贪多：

1. 更新语句 UPDATE t SET col = 值 WHERE ...
   堆表侧想清楚"原地更新"还是"删+插"，索引侧 RID 变了怎么同步 —— 你会
   对阶段 2 那句"RID 是住址不是身份"有骨肉相连的理解。
2. 删除语句 DELETE FROM t WHERE ...
   堆表标记删除 + 索引里删对应 (key, RID) 条目；想想叶子页空了要不要合并。
3. 事务多版本：给行加 begin_lsn/end_lsn，实现最简快照读。
4. B+ 树页内查找从线性改二分；堆表行格式定长化 —— 拿阶段 6 的基准当裁判，
   改完跑分，看数字说话。
5. group commit：多个提交线程共享一次 fsync，把阶段 6 ④ 的差距拉近一点。
6. 把阶段 5 的 PageStore 换成阶段 1 的落盘 Pager，让 ②③ 的"内存 vs 落盘"
   口径差消失 —— 那是完全公平的比赛。
7. 优化器雏形：多个可用索引时按谓词选择率挑一个，EXPLAIN 里看得见选择过程。

## 五、课后练习

1. 概念题（合上书答）：
   - a. 为什么页大小选 4096 而不是 64？三个理由分别是什么？
   - b. RID 为什么不能当主键用？更新一行会发生什么？
   - c. B+ 树范围扫描为什么不回头碰树？这个优势 B 树有没有？
   - d. WAL 的三条纪律，缺一条会出什么事？各举一个崩溃场景。
   - e. EXPLAIN 里 IndexScan 和 TableScan 的取舍依据是什么？为什么 TEXT 列
     在这套实现里只能 TableScan？
2. 读码题：阶段 5 修过三个 bug（页内覆盖写、内部分裂覆盖、叶子分裂不回写）。
   每个 bug 用一句话说清"错在哪、什么场景暴露、怎么修的"。说不清就回去
   把那段注释和代码重读一遍。
3. 实验题：把阶段 6 的 kN 从 20 万改成 50 万，观察 MiniDB 树高变化和各组
   倍数变化，把实测数字记在笔记本上，解释为什么树高只涨 1 层而写入时间
   涨了大约 2.5 倍。
4. 标题号活：从【四】里挑一个扩展方向做完整，附基准前后对比数字。验收
   标准和毕业设一样：零警告、退出码 0、数字真实、对账能过。
