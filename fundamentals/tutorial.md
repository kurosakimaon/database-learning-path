## 一、模块简介

徒弟啊，你会写 C++，内存、指针、容器都门儿清，
现在要学数据库，师傅先给你吃颗定心丸：
你不是从零开始，你是"换了个战场"。

数据库这东西，本质上就是"把内存里的数据放到磁盘上，
还要保证断电不丢、多人不乱、查得快"。
你学过的那些数据结构，全在这儿等着你呢——
表（table）差不多就是一个 `std::vector<Row>`；
主键（primary key）差不多就是 unordered_map 的 key，
讲究一个唯一、能定位；
索引（index）就是一棵额外的 B 树，空间换时间，你早就会；
视图（view）就是一个保存下来的查询函数，每次"调用"它现算。

这一关一共 7 个文件，三张表一个借阅系统，从头撸到尾。
学完你能做到：拿到一个需求，自己建表、写出正确的 SQL、
知道为什么这么写、知道哪儿会慢、哪儿会出错。

### 为什么先学 SQL，再学原理？

很多人一上来就啃《数据库系统概念》，
B 树、日志、MVCC、两阶段锁……啃了三个月，
结果连一条 LEFT JOIN 都写不利索。这叫本末倒置。

师傅的逻辑很简单：

1. SQL 是你每天真正要写的东西。不会写，谈不上用数据库。
2. 原理是给"用得好"服务的。你没被慢查询咬过，
   看"查询计划"就像看天书；你写过了、卡过了，
   原理一看就懂，而且记得牢。
3. 就像学 C++：你先学会用 vector、会写代码，
   再去啃分配器、内存模型、移动语义，顺序反了就是受罪。

所以这一关不跟你聊存储引擎、不谈事务隔离级别，
就一件事：把 SQL 写对、写熟、写出手感。
原理，留给下一关。

## 二、学习目标

学完本模块，你要能做到：

1. 拿到一张图（读者借书），能自己把表建出来，
   主键、外键、非空、唯一、默认值、检查约束，知道各管什么

3. JOIN 不再靠背：INNER / LEFT / RIGHT / FULL / CROSS
   五种都清楚"配不上的行是扔还是留"
4. 会用子查询、CTE（WITH）、窗口函数，
   知道 ROW_NUMBER / RANK / DENSE_RANK 差在哪儿
5. 判断一个表设计是不是有病（三范式），
   也知道什么时候该"故意不合范式"
6. 用 C++ 的 SQLite C API 把查询跑起来，
   看得懂 EXPLAIN QUERY PLAN，能用数字说清"有没有走索引"
7. 踩过的坑自己心里有数：= NULL、外键默认关闭、
   LIKE 前通配、GROUP BY 里放非聚合列

## 四、学习建议与常见坑

师傅给你划两条坎，再列一串坑。

### 第一道坎：JOIN（配合 join_visualizer.html）

JOIN 的真相就是两层 for 循环加一个 if：
拿左表每一行，去右表逐行比 ON 条件，比上了就拼成一行。
五种 JOIN 的差别只有一件事——比不上的行，扔还是留：

- INNER：配不上的两边都扔
- LEFT ：左表一行不丢，右表列补 NULL
- RIGHT：右表一行不丢（就是 LEFT 对调）
- FULL ：两边都不丢（= LEFT ∪ RIGHT）
- CROSS：不比条件，全组合（8×4=32 行）

画法：拿张纸，两列行，命中画实线，没命中画叉。
画三遍就懂了。别背口诀，背了也会忘。

### 第二道坎：GROUP BY 之后的世界（01 的第 6 节和第 11 节）

聚合把"多行"压成"一行"，压完原来的列就没了，
所以 SELECT 里只能出现"分组列 + 聚合函数"。
WHERE 在分组前筛行，HAVING 在分组后筛组。
窗口函数是另一套：它不压行，
给每一行挂一个"看别人一眼"算出来的列。
ROW_NUMBER 发号（1,2,3）、RANK 并列后跳号（1,1,3）、
DENSE_RANK 并列不跳（1,1,2）——拿 01 里那两本 39 块钱的书对照看。

### 学习方法（跟学 C++ 一模一样）

1. 先读一遍，看懂注释
2. 跑起来，看输出对不对得上注释里写的预期值
3. 改！改条件、改排序、删个 WHERE，猜结果再验证
4. 改出错了，自己先修

光看不练，等于白看。SQL 尤其如此，它错得悄无声息。

### 常见坑（每一条师傅都踩过）

1. **【SQLite 外键默认是关的】**
   定义了 REFERENCES 不报错，脏数据照样插进去。
   每个连接都得先写 `PRAGMA foreign_keys = ON;`
   这是 SQLite 的"特性"，不是你的错。

2. **【= NULL 永远不成立】**
   WHERE return_date = NULL 返回 0 行，而且不报错。
   NULL 是"未知"，跟任何值比都是 unknown，不是 true 也不是 false。
   判空必须写 IS NULL / IS NOT NULL。
   同理：NOT IN 的子查询里只要混进一个 NULL，
   整个条件一行都返回不出来。

3. **【GROUP BY 里漏列】**
   标准 SQL 会报错；SQLite 睁只眼闭只眼，
   给你返回分组里随便一行的值，看着对、其实随机。
   别占这个便宜，老老实实写全。

4. **【LIKE '%关键字%' 废掉索引】**
   索引里的值是有序的，按前缀才能走树；
   前面是通配符，开头不知道是什么，只能全表扫。
   前缀匹配 'abc%' 是可以走索引的。

5. **【LEFT JOIN + WHERE 右表列 = 值，退化成 INNER】**
   想要"左表全留"，过滤条件要写在 ON 后面，
   不是 WHERE 里。WHERE 是在 JOIN 之后才筛的，
   补 NULL 的行碰上任何条件都会被干掉。

6. **【带 ORDER BY 的 LIMIT 不能帮你少扫描】**
   排序发生在 LIMIT 之前；没有索引时，
   该扫的行、该排的行，一行都省不掉。
   不带 ORDER BY 的 `LIMIT 10` 则可以早停（拿够 10 行就收工），
   但代价是行序不保证。sql_sandbox.html 的"扫描行数"演的是前一种。

7. **【 INTEGER PRIMARY KEY 不是普通主键】**
   在 SQLite 里它就是 rowid 的别名，插入时自动分配；
   但它不是 AUTOINCREMENT——删除最后一行后，新行可能复用旧 id。
   要严格递增且永不复用，得显式写 AUTOINCREMENT（有额外开销）。
   换成 BIGINT PRIMARY KEY 就没这待遇了。移植时要小心。

8. 【02 文件跑完退出码是 1】
   那是文件里"故意插一条违反外键的数据"造成的，
   预期现象。判断标准写在文件头：
   stderr 只有那一条 FOREIGN KEY constraint failed，
   stdout 一路输出到最后一节，就说明一切正常。
