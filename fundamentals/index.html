数据库学习路线 · 第 1 关

筑基期 · 关系模型与 SQL

给会 C++ 的你：把表想成 std::vector<Row>， 主键想成 hash 容器的 key，视图想成一个保存下来的查询函数—— 你不是从零开始，这一关只是换个战场继续打地基。

🧭 为什么这一关先学 SQL，不先讲原理？

很多人一上来就啃 B 树、日志、MVCC，三个月后连 LEFT JOIN 都写不利索——本末倒置了。就像学 C++：你先学会用 vector 写程序，再去啃分配器和内存模型。没被慢查询咬过，看执行计划就像看天书；写过了、卡过了，原理一看就懂。所以这一关只干一件事：把 SQL 写对、写熟、写出手感。存储引擎、事务隔离、锁——留给下一关。

表 ≈ std::vector<Row>一行就是一条记录，列有类型、有顺序，行没有"指针"给你玩。
主键 ≈ hash 容器的 key唯一、可定位，插重复的直接拒收——跟 insert 失败一个道理。
视图 ≈ 保存下来的查询函数不存数据，每次"调用"现算；索引才是真的存了副本。

🪜 学习顺序（别乱）

  1. 读地图：通读 tutorial.md，知道两条坎和 8 个坑长什么样。
  2. 跑剧本：用 sqlite3 跑 01_sql_tour.sql，逐节对着注释里的预期值核结果；顺手把不懂的 SQL 抄进 sql_sandbox.html 改着玩。
  3. 看动画：打开 join_visualizer.html，五种模式各点一遍"下一步"，重点盯钱进（dept_id 为 NULL）和公关部（没人认领）。
  4. 学设计：跑 02_schema_design.sql，看外键报错、看大宽表一层层拆到 3NF。
  5. 写 C++：编译运行 03_sql_cpp.cpp，读懂 RAII 包装和索引对比，然后做文件末尾的 3 个练习。
  6. 交作业：做 tutorial.md【五】里的 3 道课后练习。

⌨️ 命令行速查（PowerShell）

# 进入本目录后：整体跑 SQL 剧本（-bail 表示一遇错就停，应当零报错）
sqlite3 -bail :memory: ".read 01_sql_tour.sql"

# 打开一个练习库文件（第一次跑完就留下了 readers/books/loans 三张表）
sqlite3 practice.db
sqlite> .read 01_sql_tour.sql
sqlite> .tables                    -- 看有哪些表
sqlite> .schema loans               -- 看建表语句
sqlite> .mode box                   -- 结果画成表格，好认
sqlite> SELECT name, city FROM readers WHERE city = '北京';
sqlite> .quit

# 02 会故意制造一次外键报错，所以不加 -bail；退出码 1 是预期现象
sqlite3 :memory: ".read 02_schema_design.sql"

# 编译并运行 C++ 驱动（sqlite3 开发库已在 msys2 UCRT64）
g++ -std=c++17 -Wall -Wextra 03_sql_cpp.cpp -o 03_sql_cpp.exe -lsqlite3
.\03_sql_cpp.exe
开工前记住第一条军规：SQLite 的外键约束默认是关闭的。每个新连接（每个 sqlite3 会话、每个 C++ 连接）都要先执行 PRAGMA foreign_keys = ON;， 否则脏数据照样塞进去，还不报错——这是 SQLite 的"特性"，不是你的错。
