老师傅先说一句： JOIN 的本质就是两层 for 循环 + 一个 if：拿左表每一行，去右表逐行比 ON 条件， 比上了就把两行拼成一行。INNER / LEFT / RIGHT / FULL 的差别只有一件事——比不上的行，扔还是留； CROSS 压根没有 ON，不比价，另说。 点模式按钮，再点「下一步」，一行一行看。
好消息：SQLite 从 3.39（2022 年 7 月）开始终于支持 RIGHT JOIN 和 FULL OUTER JOIN 了， 本仓库在 3.51 上验证过，五种模式全能真跑。先确认自己手上的版本： SELECT sqlite_version();（sqlite3 命令行里 .version 也一样）。 3.38 及更早版本里 RIGHT / FULL 会直接报 RIGHT and FULL OUTER JOINs are not currently supported， 老代码里那些 LEFT JOIN ... UNION ALL ... LEFT JOIN 手拼的写法就是这么来的——见到别慌，知道它在补什么。

别把「五种 JOIN 各家都有」当成常识：INNER / LEFT / CROSS 确实家家都有，RIGHT 也基本家家都有， 但 MySQL（含 8.x）到今天都不支持 FULL OUTER JOIN，PostgreSQL / SQL Server / Oracle / SQLite 3.39+ 才有。 MySQL 里的标准替身是两边各来一次 LEFT 再拼：
SELECT ... FROM a LEFT JOIN b ON b.id = a.id
UNION ALL
SELECT ... FROM b LEFT JOIN a ON a.id = b.id WHERE a.id IS NULL;
注意中间是 UNION ALL 不是 UNION：左半边的「两边都配上」的行和右半边的「只有右表有」的行本来就不重叠， 用 UNION 只是白白多一次去重排序。跨库写查询时，FULL 是唯一要提前问一句「你家数据库支持吗」的模式，面试也爱拿这条挖人。
