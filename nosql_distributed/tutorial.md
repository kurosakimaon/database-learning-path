NoSQL 和分布式这两个词，江湖上传得神乎其神，多少人张口 CAP、

> ◆ 本关的核心命题：你要的不是精通 NoSQL，而是知道边界在哪——
>   知道关系型数据库在哪里开始吃力，知道 NoSQL 各自放弃了什么、
>   换来了什么，知道分布式一旦开口，就要用一致性去付账。 ◆

## 一、模块简介 —— 为什么 C++ 后端工程师要懂 NoSQL 的边界

你写 C++，大概率跟三种活儿沾边：高性能存储/缓存组件、网关与
交易链路、或者给上层业务做基础设施。这三种活儿里，你迟早会撞上
这些问题：

1. 有人问你："Redis 和 MySQL 怎么选？" —— 这不是背 API 的问题，
   是数据模型的问题。KV、文档、列族、图，四种模型各解决一类
   访问形状（01_data_models.cpp 让你亲手把四种模型各写十行，
   十行就够了，模型的"脾气"全在里面）。

2. 有人问你："为什么 RocksDB / LevelDB 写这么快？" —— 答案是
   LSM-Tree：把随机写变成顺序写，代价是读要翻好几层、后台
   compaction 要还债。这笔账本关要用放大镜算给你看
   （02_lsm_vs_btree.cpp + lsm_animator.html 动画）。

3. 有人在会上说："我们上分布式，QPS 翻倍！" —— 你要能立刻反问：
   "复制是同步还是异步？读主还是读备？分区时选 C 还是选 A？"
   03_concurrency_cpp.cpp 用真线程把"异步复制读不到自己刚写的
   数据""并发读改写丢更新"当场复现出来，不是 PPT，是你机器上
   真丢的那几块钱。

但是——听好了——**别跑偏**。本关不教你调 Cassandra 的分区键、
不教你搭 TiKV 集群、不让你背二十种 NoSQL 的选型矩阵。那些是
"精通 NoSQL"的路，那是别人吃饭的碗。你的碗是把存储与并发的
**原理账**算明白：LSM 的写放大从哪来、布隆过滤器凭什么省掉
一次盘、异步复制为什么读不到自己的写。原理账算明白了，
市面上任何新品你十分钟就能看懂它在哪条老路上加了新料。

## 二、学习目标

学完本关，你要能做到：

1. 用自己的话说清四大 NoSQL 模型（KV / 文档 / 列族 / 图）分别
   优化什么访问形状，各自放弃了什么（事务？join？灵活 schema？）。

2. 在白板上画出 LSM-Tree 的完整生命周期：memtable 写满 → 冻结成
   immutable memtable → 顺序 flush 成 L0 有序段 → L0 攒到 4 段
   触发与 L1 的 compaction → L1 超容量再压进 L2。说清每一步
   谁在付账。

3. 背下并理解两本账的口径（与 02_lsm_vs_btree.cpp 完全一致）：
   - 写放大 = 累计落盘字节(bytesWritten) / 用户字节(userBytes)，
     LSM 典型 2~4 倍；flush 和 compaction 重写都记账。
   - 读放大 = 一次查询探测过几个段(probes)、布隆放行几个
     (bloomPassed)、真读了几个数据页(dataPageReads)。

4. 说清布隆过滤器和读放大的关系：布隆说"肯定没有"就一次盘都不碰，
   专砍"查不存在的键"这种最亏的读；它有约 1% 误判（放行白跑一趟），
   但绝不会漏。

5. 用真线程复现并解释：原子读改写为什么会丢更新；线性化为什么
   要全局锁；异步复制为什么会违背 read-your-writes；版本号/向量
   时钟怎么拦住旧值。

6. 面对"要不要上 NoSQL / 要不要分片"的灵魂拷问，能给出带代价
   清单的回答，而不是信仰式回答。

## 三、文件列表与学习重点

按下面顺序学，别跳。

### 第 1 个：01_data_models.cpp （四大模型，各写十行）

重点：

- KV（仿 Redis）：一次哈希查找，什么模型关系都不维护；
- 文档（仿 MongoDB）：嵌套 BSON 一把梭，按字段过滤扫描；
- 列族（仿 Cassandra）：按列族稀疏存储，为"一行几百万列、
  只读其中几列"而生；
- 图（仿 Neo4j）：点和边互指，遍历邻居 O(邻居数) 而不是
  O(全表)——这就是社交关系不用 join 的原因。

跑起来：

```powershell
g++ -std=c++17 -O2 01_data_models.cpp -o 01_data_models.exe
```

看每个模型末尾"老师傅的话"，那段比代码值钱。

### 第 2 个：02_lsm_vs_btree.cpp （本关账本，必须精读）

重点：

- LSMTree::put：只写内存 map（模拟 skiplist），攒到 memLimit
  条才 flush——写路径零磁盘 IO，快就快在这；
- LSMTree::get：memtable → L0 逐段(新在前) → L1..Lk（先键
  范围筛，再问布隆）——这条链就是读放大本身；
- flush：memtable 原地有序，直接顺序写成一个 SST，插到 L0
  最前面；
- compaction：L0 攒够 l0Fanout(=4) 段就与 L1 做 k 路归并，
  同键谁新谁赢，老段全部报废——报废+重写就是写放大的大头；
- 对照组 B+ 树：每次插入都可能在页中间挖洞、分裂，随机 IO；
  但查询永远只走树高 3~4 层，读放大有硬上限。

跑起来：

```powershell
g++ -std=c++17 -O2 02_lsm_vs_btree.cpp -o 02_lsm_vs_btree.exe
```

程序末尾四条结论（代价记账科目/顺序写百倍/InnoDB 求稳/
compaction 不免费），逐字读三遍。

### 第 3 个：lsm_animator.html （把第 2 个文件动起来）

双击浏览器打开。亲手往里写 key、看 memtable 冻结、flush、
L0 攒满 4 段触发 compaction；再输入一个不存在的 key 点"查询"，
看高亮一块块跳过去——那就是读放大在你眼前走位。右侧指标
面板的写放大/读放大是从动画状态真算出来的，和 02 一个口径。
玩到能预测"下一步发生什么"为止。

### 第 4 个：03_concurrency_cpp.cpp （真线程复现分布式病）

重点：

- LaggyBank：两个线程 atomic 读→算→写，余额丢更新——
  "用了原子变量"≠"操作是原子的"；
- StrongBank：互斥锁 + 线性化流水账，每一笔全序可见，代价是
  全局锁吞吐上不去——这就是强一致的价签；
- EventualCluster：异步复制，写完主立刻读备，读到旧值——
  read-your-writes 就这么没了，程序不崩，数据悄悄骗你；
- CausalReplica：带版本号复制，旧值被拦，因果保住了，
  并发的兄弟写还得靠向量时钟仲裁。

跑起来：

```powershell
g++ -std=c++17 -O2 03_concurrency_cpp.cpp -o 03_concurrency_cpp.exe
```

（需要线程库，g++ 在 Windows 下一般自带 winpthread；
若链接报错，加 -pthread 再编一次。）

### 第 5 个：cap_visualizer.html （CAP 的可视化推演）

双击打开。手动制造网络分区，看同一份数据在分区两侧各写各的，
恢复后怎么合并——线性化、因果一致、最终一致三档在图上一眼
看出代价差。和 03 是同一件事的两种讲法：03 是真线程踩坑，
这个是把坑画给你看。

## 四、学习建议与常见坑

徒弟啊，这一关的坑比知识点多，师父给你数几个最常踩的：

1. 不要把 NoSQL 当银弹。
   "MySQL 慢"有八成是索引没建好、查询写得烂、schema 拧着来——
   这些换成 Mongo 一样慢。先证明瓶颈真的在关系模型本身
   （schema 装不下、访问形状是图遍历、写吞吐真到单机上限），
   再谈换模型。换模型的学费是：丢事务、丢 join、丢成熟工具链。

2. 别在没到分布式规模前引入分片。
   分片解决的是一台机器装不下/打不满的问题。代价清单：跨分片
   查询、跨分片事务、热点再平衡、扩容搬数据、多一套运维和监控。
   三千 QPS 的项目上六个节点三个分片，不是先进，是给自己挖坑。
   判断标准朴素得很：单机垂直扩容还有余量吗？瓶颈是读是写？
   读写分离加缓存顶得住吗？三个都答"顶不住"再考虑分片。

3. LSM 的读放大与布隆过滤器是一对，必须一起理解。
   只说"LSM 读慢"是外行。准确说法：LSM 读要探测 memtable +
   L0 各段 + 下面各层，段数就是探测上限；布隆过滤器让"这个键
   肯定不在本段"的判断不碰磁盘，专治查不存在的键（缓存穿透、
   删除后残留墓碑键都靠它）。但布隆救不了"键确实存在、散在
   多个段里取最新版本"这类读——那是 compaction 的活。
   在 lsm_animator.html 里开/关布隆各查几次，看 bloomPassed
   指标的变化，比看十篇文章管用。

4. 写放大不是 bug，是 LSM 的定价方式。
   02 里算给你看：flush 一遍、compaction 再重写几遍，落盘字节
   是用户字节的 2~4 倍。买顺序写百倍吞吐，就用这个付账。
   看到"写放大 3.5x"不要慌，要问的是：这 3.5 倍是不是全顺序？
   有没有和前台读写抢带宽（write stall）？

5. "用了 atomic 就线程安全了"是新手第一大坑。
   03 的 LaggyBank 全是 atomic 操作，余额照样丢。读-改-写
   三步分开，每步再原子，合起来也不原子。要么 CAS 循环，
   要么加锁，别自作聪明。

6. 异步复制的坑不在"慢一点"，在"读到的值不报错"。
   写完主、读备读到旧值，程序拿到的是一个合法但过期的数据,
   没有任何异常。业务上就是"用户提交订单成功，刷新后订单没了"。
   对策无非三种：读主（贵）、会话保证 read-your-writes（中等）、
   业务容忍最终一致（免费但要想清楚哪些数据不能容忍）。

7. 玩 lsm_animator.html 时的坑：只看不算。
   每做一步，先盯右侧指标面板猜下一步哪个数字会动、动多少，
   再按下按钮。猜错了回去翻 02 对应代码。猜十次全对，这个
   结构才是你的。

## 五、课后练习

**练习 1（改 01）**：给 KV 模型加 expire 惰性过期——get 时检查时间戳，
过期则删除并返回 miss。再想想：为什么 Redis 用"惰性删除 +
定期抽样删除"双策略，而不是后台全表扫？
提示：全表扫的代价和 key 数量成正比，正是要避免的事。

**练习 2（改 01）**：给文档模型加一个按嵌套字段 total > 100 过滤的
查询；再给列族模型加"只读指定两列"的接口。体会两者扫描量
的差别。
提示：文档模型整条记录都在，过滤要整条解析；列族按列存，
不读的列连碰都不碰。

**练习 3（玩 lsm_animator）**：把 memLimit 调成最小，连续写入直到
触发两次 compaction。记录：第二次 compaction 时写放大倍数
比第一次大还是小？为什么 L0→L1 这次通常最贵？
提示：L0 四段键范围互相重叠，四段全要读、全要重写；
而 L1→L2 只挑范围重叠的段。

**练习 4（玩 lsm_animator）**：写入 key 后立刻查询它，记下探测数；
等它被 compaction 压到 L2 后再查一次，再记探测数。同一个键,
两次查询谁贵？布隆过滤器这时帮了谁？
提示：新键在 memtable 零 IO 命中；老键要按 L0→L1→L2 走一遍,
但沿途"肯定没有"的段都被布隆拦住了。

**练习 5（改 03）**：给 EventualCluster 加一个"读主回退"开关——
当客户端带着"上次读到的版本号"而副本版本更旧时，改读主库。
观察开关打开后 read-your-writes 违背次数归零、但主库读 QPS
上升。
提示：这就是很多中间件"会话一致性"的骨架。

**练习 6（思考题，不动代码）**：你们的 IM 消息已读状态，选 KV 还是
文档还是关系表？如果已读状态要跨设备秒级同步，异步复制能忍
吗？写出三行以内的取舍。
提示：数据形状（每用户每会话一个 bool）、访问模式（高频小
写 + 读己之写）、丢了会怎样（红点消了又亮，用户骂但能忍）。
