数据库学习路线 · 第 2 关

炼气期 · 存储与索引

给会 C++ 的你：页就是一块定长的 mmap 区域， Buffer Pool 就是带淘汰策略的对象池，B+ 树节点就是定长结构体里塞 key 数组 + 孩子页号——把 vector 下标存进文件， 你就已经懂了一半存储引擎。

◆ 本关唯一要刻进脑子的一句话：数据库的一切设计，都源于"磁盘按页读写、 内存断电即失"这对矛盾。Buffer Pool 对抗慢，WAL 对抗断电， B+ 树对抗"按页读写"——没有一样发明是凭空来的。

🧭 先算两本账，再谈数据结构

这一关看任何方案，都先分两个本记账。只看比较次数，你会得出 "要 B+ 树干嘛"的错误结论；账本一换，结论立刻翻转。

CPU 的账：比较次数 一次比较约 1ns，十亿次才一秒。
红黑树点查 ≈ 18 次比较，看着真漂亮——
磁盘的账：页读取次数 一次随机 I/O ≈ 100μs = 十万次比较。
同样这棵树散在磁盘上就是 18 次随机 I/O； B+ 树树高 4，只要 4 页。账本一换，高下立判。
扇出决定树高一个节点 = 一页 = 101 个分叉；log₁₀₁(100万) ≈ 3。红黑树节点挂着数据，扇出被拖死。
偏移不是指针页里存"到页心的偏移"。内存地址是临时工，页号+偏移才是户口本——01 里亲手体会。
省了读，欠了写Buffer Pool 挡住 20 次读，就可能欠 1 次脏页写回。写放大、checkpoint 全从这笔账长出来。

🪜 建议的学习顺序

  1. 通读 tutorial.md——先接受那句核心命题，带着"谁是被逼出来的"这个问题往下看。
  2. 跑 01_disk_and_page.cpp——先造页，再造 Pager，最后造 Buffer Pool。看命中率怎么爬上去、脏页怎么写回。
  3. 边玩 btree_animator.html 边读 02_btree_vs_sorted_array.cpp——动画里看清分裂规则（叶子复制上提、内部上提不留），再去 02 看阶 101 的真树怎么长成 4 层。
  4. 跑 03_index_in_practice.sql——每条 EXPLAIN 先猜再看注释；把"SCAN 还是 SEARCH"练成本能。
  5. 玩 bufferpool_animator.html——同一条序列 LRU、Clock 各跑一遍，比较命中率；点「制造缓存污染」看热页死亡回放。
  6. 做 tutorial.md 末尾的三道练习——砍扇出重跑 02、纸上画阶 4 插入、当 EXPLAIN 预言家。做完这一关才算通关。
