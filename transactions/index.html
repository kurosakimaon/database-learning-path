database-learning-path › 第 3 关

心法期 · 事务与 ACID

接口只有四个词：BEGIN / COMMIT / ROLLBACK / SAVEPOINT。
这一关让你在真线程、真锁、真页缓存里，把事务的每种死法都亲手过一遍。

学法约定：每个 .cpp 都必须自己编译运行；输出里的毫秒时间线是灵魂 —— 交错是真实发生的，不是画出来的。

学习路线（按顺序，别跳）

01_acid_in_sqlite.sql —— 用 SQL 亲手验证 ACID
显式事务、ROLLBACK、SAVEPOINT 部分回滚、WAL 模式、两个会话互相锁门。
重点感受：COMMIT 之前一切都还是「租的」，ROLLBACK 一键退还。 sqlite3 :memory: ".read 01_acid_in_sqlite.sql"
02_transaction_raii.cpp —— 把事务装进析构函数
RAII 事务类 + SQLITE_BUSY 指数退避重试 + 两线程写同一行。
重点感受：BUSY 不是失败是「待会儿再来」，吞掉 BUSY = 悄悄丢更新。 g++ -std=c++17 -O2 02_transaction_raii.cpp -o t02.exe -lsqlite3 && .\t02.exe
03_isolation_anomaly_lab.cpp —— 异常复现车间（核心）
真多线程真连接：脏读、不可重复读、丢失更新、写写冲突全部现场复现； 原子 UPDATE / 悲观锁 / 乐观锁 CAS 三种修法实测都做到分毫不差。
重点感受：sqlite 的 BUSY / LOCKED 报错就是「隔离性在挣扎」的动静。 g++ -std=c++17 -O2 03_isolation_anomaly_lab.cpp -o t03.exe -lsqlite3 && .\t03.exe
04_lock_and_deadlock.cpp —— 手搓锁管理器（珠峰）
S/X 锁 + FIFO 等待队列 + 锁升级 + 等待图找环 + 受害者回滚重试； 实测随机加锁死锁率 11.6% vs 排序加锁 0%。
重点感受：行锁 ≈ 按 key 分片的 mutex；死锁检测 ≈ 等待图找环。 g++ -std=c++17 -O2 04_lock_and_deadlock.cpp -o t04.exe && .\t04.exe
